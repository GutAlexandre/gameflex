# Photos des consoles

Les 33 plateformes affichées utilisent des photographies locales du matériel. Les images sont redimensionnées à 960 px maximum, converties en WebP et affichées sans recadrage. Les crédits sont visibles dans les cartes et dans Paramètres › Crédits des images.

32 photographies viennent de Wikimedia Commons, sous domaine public ou CC BY-SA. La photographie CPS-2 vient de Flickr, découverte par Openverse ; sa licence CC BY-NC-SA 2.0 est confirmée sur la page originale. Elle est réservée à un usage non commercial et reste sous cette licence lors de sa redistribution. Le script exige `--allow-noncommercial` pour cet import explicite.

Doom représente un moteur PC : sa carte affiche un IBM PS/2 Model 70, pas une console dédiée. Les photos correspondent à une variante réelle de chaque famille : par exemple Game Boy Color pour la famille GB/GBC, DS Lite pour DS et SNES américain pour SNES. Les cartes CPS représentent leur matériel arcade.

Sources de découverte : [galerie Evan-Amos](https://commons.wikimedia.org/wiki/User:Evan-Amos), API Wikimedia Action, et [Openverse](https://api.openverse.org/v1/) pour la seule photographie CPS-2. Les droits sont vérifiés auprès de la source originale, pas déduits d’un résultat de recherche. Openverse est consulté ponctuellement sans clé ; aucun appel à Openverse ou Flickr n’est effectué depuis les cartes affichées. Respecter les quotas signalés par le service et les réponses 429, sans boucle de réessai.

Les métadonnées complètes sont dans `output/console-photos/credits.json` et chaque fichier JSON associé. Le catalogue versionné de sources est `deploy/pi-tv/console-photos.json`. Le cache actif reste dans `.local/pi-tv/media` ; les copies consultables sont dans `output/console-photos/`.

Pour réimporter les sources sélectionnées, utiliser un environnement Python avec Pillow puis :

```sh
python3 tools/pi-tv/import-console-photos.py --allow-noncommercial
```

Aucune image de jeu, ROM, BIOS ou firmware n’est recherchée ou téléchargée par cet import de matériel. Les images conservées sont des photos de machines, consoles, composants ou cartes arcade.

Les métadonnées d’images sont chargées avec `cache: no-store`, avec trois relances temporisées en cas de panne temporaire. Le service worker exclut toutes les routes `/experience-api/` de son cache de ressources statiques, comme les autres API ; une ancienne liste vide ne peut donc plus persister. Les photos restent servies par leur empreinte depuis le cache local du Pi.
